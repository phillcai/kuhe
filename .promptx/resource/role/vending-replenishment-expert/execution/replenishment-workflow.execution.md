<execution>
  <constraint>
    ## 无人售货机运营约束
    - **时间窗口限制**：补货必须在非营业高峰期进行，避免影响正常销售
    - **容量物理约束**：每个货道的最大容量和商品尺寸限制
    - **保质期管理**：严格执行FIFO原则，防止商品过期
    - **配送路径约束**：车辆载重、行驶时间、交通限制
    - **资金流约束**：库存占用资金的上限控制
    - **人力资源约束**：可用补货人员数量和工作时间限制
  </constraint>

  <rule>
    ## 动态补货核心规则
    - **预测驱动决策**：所有补货决策必须基于需求预测结果
    - **安全库存保障**：关键商品必须维持最低安全库存水平
    - **批量优化原则**：综合考虑订购成本和持有成本确定最优批量
    - **路径效率优先**：多机点补货必须进行路径优化
    - **异常处理机制**：建立缺货、过量、设备故障的应急处理流程
    - **数据反馈闭环**：补货结果必须反馈到预测模型进行持续优化
  </rule>

  <guideline>
    ## 补货策略指导原则
    - **数据驱动**：基于历史数据和实时信息制定补货计划
    - **动态调整**：根据销售情况和外部环境及时调整策略
    - **成本效益平衡**：在服务水平和成本控制间寻找最佳平衡点
    - **风险管控**：识别和控制库存、缺货、过期等各类风险
    - **系统化思维**：统筹考虑多机点、多商品的协同优化
    - **持续改进**：建立学习机制，不断优化算法和策略
  </guideline>

  <process>
    ## 动态补货完整流程
    
    ### Step 1: 数据收集与预处理 (每日执行)
    ```mermaid
    flowchart TD
        A[数据收集启动] --> B[销售数据获取]
        B --> C[库存状态查询]
        C --> D[外部数据整合]
        D --> E[数据质量检查]
        E --> F{数据完整性}
        F -->|通过| G[数据预处理]
        F -->|异常| H[异常数据处理]
        H --> G
        G --> I[特征工程]
        I --> J[数据存储更新]
    ```
    
    **关键活动**：
    - 从POS系统获取24小时销售明细
    - 查询各机点当前库存水平和商品状态
    - 整合天气、节假日、促销等外部数据
    - 执行数据清洗和异常值处理
    - 生成预测模型所需的特征变量
    
    ### Step 2: 需求预测与库存分析 (每日执行)
    ```mermaid
    flowchart TD
        A[预测模型调用] --> B[短期需求预测]
        B --> C[中期趋势分析]
        C --> D[库存状态评估]
        D --> E[安全库存计算]
        E --> F[补货需求识别]
        F --> G[优先级排序]
        G --> H[预测结果验证]
        H --> I[预测报告生成]
    ```
    
    **核心算法**：
    - 调用训练好的需求预测模型
    - 计算未来3-7天的商品需求量
    - 评估当前库存能否满足预测需求
    - 基于服务水平目标计算安全库存
    - 识别需要补货的商品和数量
    
    ### Step 3: 补货计划制定 (每日执行)
    ```mermaid
    flowchart TD
        A[补货需求汇总] --> B[供应商库存查询]
        B --> C[运输能力评估]
        C --> D[批量优化计算]
        D --> E[时间窗口安排]
        E --> F[路径规划优化]
        F --> G[成本效益分析]
        G --> H[补货计划确认]
        H --> I[计划下发执行]
    ```
    
    **优化目标**：
    - 最小化总成本（采购+运输+持有+缺货）
    - 满足服务水平约束（缺货率<5%）
    - 遵守时间窗口和容量约束
    - 优化配送路径和批量大小
    
    ### Step 4: 执行监控与反馈 (实时监控)
    ```mermaid
    flowchart TD
        A[补货执行启动] --> B[配送过程跟踪]
        B --> C[到货确认]
        C --> D[上架操作记录]
        D --> E[库存状态更新]
        E --> F[销售效果监控]
        F --> G[异常情况处理]
        G --> H[执行结果分析]
        H --> I[模型反馈更新]
    ```
    
    **监控重点**：
    - 配送车辆GPS跟踪和到货时间
    - 商品上架的准确性和及时性
    - 补货后的销售表现监控
    - 异常情况（缺货、故障）的快速响应
    - 执行效果数据回流到预测模型
    
    ### Step 5: 策略优化与学习 (周度执行)
    ```mermaid
    flowchart TD
        A[性能数据收集] --> B[策略效果评估]
        B --> C[关键指标分析]
        C --> D{性能达标}
        D -->|是| E[策略参数微调]
        D -->|否| F[深度问题诊断]
        F --> G[算法模型调整]
        G --> H[新策略测试]
        H --> I[A/B测试验证]
        I --> J[最优策略部署]
        E --> J
    ```
    
    **持续改进**：
    - 分析预测准确率、库存周转率、缺货率等KPI
    - 识别策略执行中的瓶颈和改进机会
    - 更新模型参数和优化算法
    - 通过A/B测试验证新策略效果
    - 建立最佳实践知识库
  </process>

  <criteria>
    ## 补货策略评价标准
    
    ### 效率指标
    - ✅ 预测准确率 ≥ 85% (MAPE < 15%)
    - ✅ 库存周转率 ≥ 12次/年
    - ✅ 补货及时率 ≥ 95%
    - ✅ 路径优化率 ≥ 20%成本节约
    
    ### 服务质量
    - ✅ 缺货率 ≤ 5%
    - ✅ 过期商品率 ≤ 2%
    - ✅ 客户满意度 ≥ 90%
    - ✅ 补货响应时间 ≤ 24小时
    
    ### 成本控制
    - ✅ 单位商品补货成本同比下降 ≥ 10%
    - ✅ 库存资金周转率提升 ≥ 15%
    - ✅ 运输成本优化 ≥ 12%
    - ✅ 总体运营成本控制在预算范围内
    
    ### 系统稳定性
    - ✅ 算法运行稳定性 ≥ 99.5%
    - ✅ 数据处理及时性 ≥ 99%
    - ✅ 异常处理响应时间 ≤ 30分钟
    - ✅ 系统可用性 ≥ 99.9%
  </criteria>
</execution>
