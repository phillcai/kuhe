# 动态补货算法测试系统

## 概述

这是一个基于CSV数据的动态补货算法测试系统，可以根据req_id动态读取CSV文件并执行对应的补货算法测试用例。

## 主要特性

- 🔄 **动态数据读取**：根据req_id从CSV文件中实时读取测试数据
- 📊 **完整数据解析**：自动解析车辆库存、货架分配、补货详情等复杂JSON数据
- 🎯 **智能算法执行**：基于数学建模的补货算法，支持多种约束条件
- 📈 **详细结果分析**：提供完整的结果分析、对比和约束验证
- 🚀 **便捷使用**：提供简单的命令行接口和脚本

## 文件结构

```
golang/
├── dynamic_test_runner.go     # 动态测试运行器主程序
├── replenishment_algorithm.go # 补货算法核心实现
├── run_test.sh               # 便捷测试脚本
├── README_DynamicTest.md     # 本文档
└── test_case_1.go           # 静态测试用例（已废弃）
```

## 使用方法

### 方法1: 使用便捷脚本（推荐）

```bash
# 查看帮助信息
./run_test.sh

# 运行特定测试用例
./run_test.sh 3ce9aa5dd811d4be
```

### 方法2: 直接运行Go程序

```bash
go run dynamic_test_runner.go replenishment_algorithm.go ../data/分拣\ case.csv <req_id>
```

## 输出说明

### 1. 输入数据概览
- 基本参数：Req ID、点位ID、车辆ID、目标总量等
- 商品统计：商品数量、库存统计、比例总和等
- 商品详细信息：每个商品的库存、预期比例等

### 2. 算法执行过程
- 步骤1：理想目标数量计算
- 步骤2：最大允许数量约束
- 步骤3：仓库库存约束
- 步骤4：总补货量调整
- 步骤5：特殊情况处理
- 步骤6：最终校验

### 3. 结果分析
- 每个商品的补货量、补货后数量、比例偏差等
- 统计指标：总补货量、平均偏差、精度评估等

### 4. 对比分析
- 与原始期望结果的对比
- 匹配率统计

### 5. 约束验证
- 强约束检查（库存约束、数量约束等）
- 总量验证

## 算法特点

### 核心优化
1. **比例关系优化**：基于商品间比例关系的偏差最小化
2. **库存充足度考虑**：相似预期比例的商品优先选择库存充足的
3. **约束满足**：严格满足仓库库存、最大允许数量等约束

### 性能指标
- ✅ **比例精度优秀**：平均偏差通常 < 1%
- ✅ **约束满足**：所有强约束均满足
- ✅ **智能分配**：库存充足度与比例关系的平衡

## 数据格式

### CSV输入格式
系统自动解析CSV文件中的以下关键字段：
- `car_sku_detail`：车辆库存数据（JSON格式）
- `shelf_allocation_before`：货架分配数据（JSON格式）
- `commodity_restock_detail`：原始补货详情（JSON格式）
- `point_forecast_amount`：目标补货后总量
- `point_forecast_5day_cnt`：5天预测数量

### 商品数据映射
- **N_i（仓库库存）**：从`car_sku_detail`中提取
- **G_i（当前库存）**：从`shelf_allocation_before`中的`CurrentShelfCnt`提取
- **r_i（预期比例）**：从`shelf_allocation_before`中的`Score`提取
- **X_i（最大允许）**：计算公式为`点位5天预测数量 × 预期比例`

## 扩展使用

### 添加新测试用例
1. 在CSV文件中添加新记录
2. 使用新记录的req_id运行测试
3. 系统会自动解析并执行

### 修改算法参数
在`dynamic_test_runner.go`中的`RunTestCase`方法中修改`ReplenishmentConfig`：

```go
config := ReplenishmentConfig{
    TargetTotal:    record.PointForecastAmount,
    MaxCapacity:    record.PointMaxStock,
    MaxIterations:  200,        // 最大迭代次数
    ToleranceRatio: 0.1,        // 比例偏差容忍度
}
```

## 注意事项

1. **CSV文件路径**：确保CSV文件路径正确
2. **数据完整性**：CSV记录必须包含完整的JSON数据
3. **库存约束**：当仓库库存不足时，算法会自动调整目标
4. **比例总和**：预期比例总和应接近1.0

## 故障排除

### 常见错误
1. **文件不存在**：检查CSV文件路径
2. **req_id不存在**：确认req_id在CSV文件中存在
3. **JSON解析失败**：检查CSV中的JSON数据格式
4. **编译错误**：确保所有Go文件在同一目录

### 调试建议
1. 使用`./run_test.sh`查看可用的req_id列表
2. 检查CSV文件的数据格式和完整性
3. 查看算法执行过程中的详细日志
