# 点位聚类和时间窗口分析 - Go版本

这是原Python脚本的Go语言重写版本，用于将点位按地理位置进行动态分区，并统计每组的时间窗口分布，支持数量均衡和时间窗分散优化。

## 功能特性

1. **CSV数据读取**: 从`data/点位信息.csv`文件读取点位信息
2. **数据过滤**: 自动过滤掉pid为998和999的点位
3. **K-means聚类**: 基于经纬度进行地理聚类
4. **数量均衡**: 确保各组点位数量相对均衡
5. **时间窗口优化**: 对9:00-21:00时间段的点位进行分散优化
6. **离群点处理**: 自动检测并修正地理离群点
7. **孤立点归组**: 将极端孤立的点位分配到最近的分组
8. **结果输出**: 生成详细的分组报告和CSV文件

## 输入数据格式

### 点位信息CSV文件
CSV文件应包含以下列：
- `id`: 点位ID
- `longitude`: 经度
- `latitude`: 纬度
- `start_time`: 开始时间 (HH:MM格式)
- `end_time`: 结束时间 (HH:MM格式)

### 行驶时长CSV文件（可选）
如果提供行驶时长数据，程序将使用优化的聚类算法。文件格式如下：

```
点位ID,点位1,点位2,点位3,...
1,0,15,25,...
2,15,0,20,...
3,25,20,0,...
...
```

- 第一行：表头，包含"点位ID"和各点位的ID
- 第一列：起始点位ID
- 其他列：从起始点位到目标点位的行驶时长（分钟）
- 对角线元素：通常为0（同一点位）
- 缺失数据：用空值或"-"表示

**示例**：
```
点位ID,1,2,3,4,5
1,0,15,25,30,20
2,15,0,20,25,15
3,25,20,0,10,30
4,30,25,10,0,25
5,20,15,30,25,0
```

**注意事项**：
1. 行驶时长数据是可选的，如果没有提供，程序将使用传统的地理距离聚类
2. 行驶时长矩阵应该是对称的（从A到B的时长等于从B到A的时长）
3. 时长单位为分钟
4. 无效数据用空值或"-"表示

## 算法流程

### 传统聚类流程（无行驶时长数据）
1. **数据预处理**: 读取CSV文件，过滤无效点位，合并同一ID的多个时间窗口
2. **K-means聚类**: 使用经纬度进行3组聚类
3. **数量均衡**: 通过移动边界点实现各组数量均衡
4. **时间窗口优化**: 对9:00-21:00时间段的点位进行分散优化
5. **数量再均衡**: 均衡每组主时间窗点位的数量
6. **离群点处理**: 检测并修正地理离群点
7. **孤立点归组**: 处理极端孤立的点位

### 优化聚类流程（有行驶时长数据）
1. **数据预处理**: 读取点位信息和行驶时长数据，过滤无效点位
2. **特征计算**: 计算每个点位的综合特征向量（经度、纬度、平均行驶时长）
3. **优化K-means聚类**: 使用基于行驶时长的距离度量进行聚类
4. **数量均衡**: 通过移动边界点实现各组数量均衡
5. **时间窗口优化**: 对9:00-21:00时间段的点位进行分散优化
6. **数量再均衡**: 均衡每组主时间窗点位的数量
7. **离群点处理**: 检测并修正基于行驶时长的离群点
8. **孤立点归组**: 处理极端孤立的点位

### 距离计算优化
- **传统方法**: 使用欧几里得距离计算经纬度之间的直线距离
- **优化方法**: 结合行驶时长和地理距离的综合距离计算
  - 距离权重: 0.3（地理距离）
  - 时间权重: 0.7（行驶时长）
  - 综合距离 = 0.3 × 地理距离 + 0.7 × 行驶时长

## 参数配置

主要参数可以在`main.go`中调整：

### 基础参数
- `nClusters`: 聚类组数（默认3）
- `minInterval`: 时间窗口最小间隔（默认120分钟）
- `maxIter`: 离群点处理最大迭代次数（默认5）
- `stdFactor`: 离群点判定标准差倍数（默认2）
- `thresholdKm`: 孤立点归组阈值（默认20公里）

### 行驶时长优化参数
- `timeWeight`: 行驶时长权重（默认0.7）
- `geoWeight`: 地理距离权重（默认0.3）
- `defaultTravelTime`: 缺失行驶时长数据的默认值（默认1000分钟）

### 特征计算参数
- `featureDimensions`: 特征向量维度（默认3：经度、纬度、平均行驶时长）
- `normalizationMethod`: 数据标准化方法（Z-score或Min-Max）

## 基于行驶距离和行驶时长的聚类优化

### 问题分析

当前算法使用经纬度计算欧几里得距离存在以下局限性：

1. **直线距离 vs 实际距离**: 经纬度计算的是直线距离，但实际道路网络可能有绕行、单行道、拥堵等情况
2. **距离 vs 时间**: 相同距离的路段，由于路况不同，行驶时长可能差异很大
3. **路网拓扑**: 忽略实际道路网络的拓扑结构，可能导致聚类结果不符合实际配送需求

### 优化思路

#### 方案1：基于行驶距离的聚类
**核心思想**: 使用实际行驶距离替代直线距离
- **优点**: 更贴近实际配送距离，考虑道路网络约束
- **缺点**: 可能忽略时间因素，距离远但时间短的情况
- **适用场景**: 距离是主要成本因素的配送场景

#### 方案2：基于行驶时长的聚类
**核心思想**: 使用行驶时长作为距离度量
- **优点**: 更贴近实际配送时间成本，考虑路况和交通状况
- **缺点**: 可能忽略距离因素，时间短但距离远的情况
- **适用场景**: 时间是主要约束因素的配送场景

#### 方案3：综合距离和时长的加权聚类（推荐）
**核心思想**: 结合行驶距离和行驶时长，设计综合成本函数
- **优点**: 平衡距离和时间两个维度，更符合实际业务需求
- **缺点**: 权重设置需要经验或调参
- **适用场景**: 距离和时间都重要的综合配送场景

#### 方案4：分层聚类策略
**核心思想**: 分阶段使用不同的距离度量
- **第一阶段**: 基于行驶距离进行粗聚类
- **第二阶段**: 基于行驶时长进行细调
- **优点**: 结合两种优势，算法相对简单
- **缺点**: 可能陷入局部最优
