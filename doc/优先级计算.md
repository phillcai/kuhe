目标: 对所有召回的待补货点位进行优先级排序

核心因素:

1. 缺货风险（最重要）
定义：点位在未来一段时间内发生缺货的概率或紧迫程度。
计算方式：可根据当前库存、销量预测、补货周期等推算出预计缺货时间，越早缺货优先级越高。
示例：预计2小时后缺货的点位优先级高于预计8小时后缺货的点位。

2. 预计销量
定义：点位在补货周期内的总销量预测。
作用：销量高的点位补货优先级更高，因为影响营业额和客户体验更大。

3. 点位类型/重要性
定义：如"大点位""新点位""中点位""小点位"等，或特殊战略点位。
作用：大点位、新点位等通常优先级更高。


关于补货评估窗口:
  - 对于补货极度受限的点位，可单独设定优先级加分项，而不是直接拉长窗口
  - 目前的窗口是 6 小时, 不能完全覆盖高峰期/低谷期的动态需求波动, 可以适当拉长, 引入的风险是?
  



# 补货点位优先级计算方法汇总

## 思路一：

### 1. 公式
- 对每一项分值进行标准化（归一化）：
  - 缺货风险分标准化：
    stockout_score_norm = (stockout_score - min(stockout_score)) / (max(stockout_score) - min(stockout_score))
  - 预计销量分标准化：
    sales_score_norm = (sales_score - min(sales_score)) / (max(sales_score) - min(sales_score))
  - 类型分标准化（如有必要）：
    type_score_norm = (type_score - min(type_score)) / (max(type_score) - min(type_score))
- 最终优先级：
  priority = w1 * stockout_score_norm + w2 * sales_score_norm + w3 * type_score_norm

### 2. 参数说明
- stockout_score：预计缺货小时数
- sales_score：预测销量
- type_score：如大点位1.0，新点位0.8，中点位0.5，小点位0.3
- w1, w2, w3：权重，推荐w1=0.6, w2=0.25, w3=0
- 排序时应按 priority 从大到小排序，分值越大优先级越高


### 3. 好处
- 消除量纲影响，提升排序公平性
- 区分度更高，适应动态数据分布
- 便于与其他归一化算法融合

### 4. 注意事项
- 若某项分值极差为0，建议赋0.5（中值）或根据业务实际处理，避免分母为0
- 类型分如为离散值，标准化意义有限，可视业务需求决定是否标准化

## 思路二：

### 1. 公式
Ri = min(Si - Fi, 30)

P = a * (1 - (Ri - min(R)) / (max(R) - min(R))) + (1 - a) * ((order_i - min(order)) / (max(order) - min(order)))

### 2. 参数说明
- Si：点位当前库存
- Fi：点位未来6小时销量预测
- Ri：缺货程度，最多截断为30
- order_i：点位销量预测
- a：权重，工作日白天a=0.2（优先大点位），其他时段a=0.8（优先缺货程度）

### 3. 讨论点
- 适合业务上对大点位和缺货程度有不同时间段侧重
- 固定阈值 30 的考量, 区分点位类型吗?
- 没有考虑sku 不足的因素
- 忽略上一个点的话, 缺货紧急程度可以考入引入分时因子
  
# 计算加权缺货指标（示例）
F_i_1h = 未来1小时销量预测
F_i_6h = 未来6小时销量预测

# 权重分配：近实时（1小时）占50%，6小时占30%，24小时占20%
