# 缺货率指标计算方案

## 1. 现有方案分析

### 1.1 当前缺货率计算方式
```
缺货率 = 缺货点位数 / 总点位数
```
**缺货定义**：点位SKU数量 < 8

### 1.2 现有方案问题
- **二元化问题**：只有缺货/不缺货两种状态，无法区分缺货程度
- **忽略缺货程度**：SKU=1和SKU=6的缺货程度被同等对待
- **忽略缺货时长**：缺货1小时和缺货1天被同等对待
- **缺乏时间维度**：无法反映缺货的持续性和趋势

## 2. 盒菜充足率SQL分析

### 2.1 SQL逻辑解析
```sql
-- 内层查询：统计每个会话中有库存的菜品数量
SELECT dt, point_id, session_id, COUNT(DISTINCT commodity_id) AS online_dish_cnt
FROM t_user_bhv_dish
WHERE stock > 0 AND commodity_type = 1
GROUP BY dt, point_id, session_id

-- 点位信息：根据设备类型设置SKU容量
SELECT id, CASE WHEN device_type = 1 THEN 15
                WHEN device_type = 5 THEN 10 ELSE 15 END AS sku_cnt
FROM t_point

-- 最终计算：充足率 = 平均(有库存菜品数 / 点位SKU容量)
SELECT AVG(online_dish_cnt / sku_cnt) AS 菜品充足度
```

### 2.2 合理性评价

**优点：**
- ✅ 考虑了不同设备类型的容量差异
- ✅ 基于实际用户会话数据，反映真实使用情况
- ✅ 按日期统计，可以观察趋势变化
- ✅ 只统计有库存的菜品，避免缺货影响

**问题：**
- ❌ 只统计有库存的菜品，没有直接反映缺货情况
- ❌ 没有考虑缺货时长和缺货影响程度
- ❌ 充足率计算可能被高估（分母是所有SKU，分子是实际有库存的）

## 3. 新的缺货指标计算方案

### 3.1 核心指标：综合缺货率（Comprehensive Shortage Rate）

```
综合缺货率 = Σ(缺货程度系数 × 缺货时长) / (总时长)
```

**缺货定义**：点位SKU数量 < 8

### 3.2 分层指标体系

#### 3.2.1 基础缺货率（Basic Shortage Rate）
```
基础缺货率 = Σ(缺货点位数) / (总点位数 × 统计周期)
```
- **用途**：反映整体缺货程度
- **计算**：统计周期内缺货点位总数除以总点位数
- **缺货定义**：SKU数量 < 8

#### 3.2.2 加权缺货率（Weighted Shortage Rate）
```
加权缺货率 = Σ(缺货程度系数 × 缺货点位数) / (总点位数 × 统计周期)
```
- **用途**：考虑不同缺货程度的加权缺货率
- **系数**：基于SKU数量的缺货程度系数

#### 3.2.3 时长缺货率（Duration-based Shortage Rate）
```
时长缺货率 = Σ(缺货程度系数 × 缺货时长) / (总时长)
```
- **用途**：反映缺货的持续性和严重程度
- **计算**：缺货程度系数乘以缺货时长，累计后除以总时长

#### 3.2.4 综合缺货率（Comprehensive Shortage Rate）
```
综合缺货率 = Σ(缺货程度系数 × 缺货时长) / (总时长)
```
- **用途**：综合考虑缺货程度和缺货时长的核心指标
- **计算**：缺货程度系数乘以缺货时长，累计后除以总时长

### 3.3 权重和系数设计

#### 3.3.1 缺货程度系数（基于SKU数量）
| SKU数量 | 缺货程度 | 系数 | 说明 |
|---------|----------|------|------|
| 0-1 | 严重缺货 | 3.0 | 几乎无货可卖 |
| 2-3 | 重度缺货 | 2.5 | 严重缺货 |
| 4-5 | 中度缺货 | 2.0 | 明显缺货 |
| 6-7 | 轻度缺货 | 1.5 | 轻微缺货 |
| ≥8 | 正常 | 0 | 不缺货 |

#### 3.3.2 时长系数
| 缺货时长 | 系数 | 说明 |
|----------|------|------|
| 短期缺货（<2小时） | 0.5 | 临时缺货，影响较小 |
| 中期缺货（2-8小时） | 1.0 | 正常缺货影响 |
| 长期缺货（>8小时） | 1.5 | 严重缺货，影响较大 |

### 3.4 时间维度设计

#### 3.4.1 统计周期
- **实时监控**：每小时更新
- **日常分析**：每日统计
- **趋势分析**：每周/每月汇总

#### 3.4.2 时间窗口
- **短期窗口**：1-4小时（实时补货决策）
- **中期窗口**：1-3天（补货计划调整）
- **长期窗口**：1-4周（供应链优化）

## 4. 实施建议

### 4.1 数据收集要求
1. **库存数据**：实时库存状态，精确到SKU级别
2. **销量数据**：SKU销量统计，用于权重计算
3. **时间数据**：缺货开始和结束时间
4. **用户行为数据**：用户访问和购买行为

### 4.2 计算优先级
1. **第一阶段**：实施基础缺货率和时长缺货率
2. **第二阶段**：加入SKU权重，实施加权缺货率
3. **第三阶段**：实施综合缺货率

### 4.3 监控阈值
| 指标 | 优秀 | 良好 | 需改进 | 严重 |
|------|------|------|--------|------|
| 基础缺货率 | <5% | 5-10% | 10-20% | >20% |
| 时长缺货率 | <2% | 2-5% | 5-10% | >10% |
| 综合缺货率 | <3% | 3-8% | 8-15% | >15% |

## 5. SQL实现示例

### 5.1 基础缺货率计算
```sql
SELECT 
    dt,
    COUNT(DISTINCT CASE WHEN sku_count < 8 THEN point_id END) AS shortage_point_count,
    COUNT(DISTINCT point_id) AS total_point_count,
    COUNT(DISTINCT CASE WHEN sku_count < 8 THEN point_id END) * 1.0 / 
    COUNT(DISTINCT point_id) AS basic_shortage_rate
FROM t_point_sku_status
WHERE dt >= '2024-01-01'
GROUP BY dt
```

### 5.2 加权缺货率计算
```sql
SELECT 
    dt,
    SUM(CASE WHEN sku_count < 8 THEN 
        CASE 
            WHEN sku_count <= 1 THEN 3.0
            WHEN sku_count <= 3 THEN 2.5
            WHEN sku_count <= 5 THEN 2.0
            WHEN sku_count <= 7 THEN 1.5
            ELSE 0 
        END 
        ELSE 0 END) AS weighted_shortage_score,
    COUNT(DISTINCT point_id) AS total_point_count,
    SUM(CASE WHEN sku_count < 8 THEN 
        CASE 
            WHEN sku_count <= 1 THEN 3.0
            WHEN sku_count <= 3 THEN 2.5
            WHEN sku_count <= 5 THEN 2.0
            WHEN sku_count <= 7 THEN 1.5
            ELSE 0 
        END 
        ELSE 0 END) * 1.0 / 
    COUNT(DISTINCT point_id) AS weighted_shortage_rate
FROM t_point_sku_status
WHERE dt >= '2024-01-01'
GROUP BY dt
```

### 5.3 综合缺货率计算
```sql
SELECT 
    dt,
    SUM(CASE WHEN sku_count < 8 THEN 
        CASE 
            WHEN sku_count <= 1 THEN 3.0
            WHEN sku_count <= 3 THEN 2.5
            WHEN sku_count <= 5 THEN 2.0
            WHEN sku_count <= 7 THEN 1.5
            ELSE 0 
        END * shortage_duration_hours
        ELSE 0 END) AS comprehensive_shortage_score,
    SUM(shortage_duration_hours) AS total_duration,
    SUM(CASE WHEN sku_count < 8 THEN 
        CASE 
            WHEN sku_count <= 1 THEN 3.0
            WHEN sku_count <= 3 THEN 2.5
            WHEN sku_count <= 5 THEN 2.0
            WHEN sku_count <= 7 THEN 1.5
            ELSE 0 
        END * shortage_duration_hours
        ELSE 0 END) * 1.0 / 
    SUM(shortage_duration_hours) AS comprehensive_shortage_rate
FROM t_point_sku_status_with_duration
WHERE dt >= '2024-01-01'
GROUP BY dt
```

## 6. 总结

新的缺货指标体系通过多维度、多层次的指标设计，能够更准确地反映点位的缺货状况，为运营决策提供更科学的数据支持。建议分阶段实施，逐步完善数据收集和计算逻辑。
