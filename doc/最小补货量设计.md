# 最小补货量设计（峰前有效补满 + 冷却锁 + 跳过阈值）

本文档在不涉及代码实现的前提下，明确“最小补货量”的业务含义、计算口径与与全排列路径评估的衔接方式，重点引入“高峰识别”“峰前有效补满”和“冷却锁”以避免高销点在同日被多次小补。

## 1. 目标与范围
- 替代固定最小补货量20，使用“动态最小补货量阈值”。
- 每次补货覆盖未来5天销量的需求上限，且不超过点位容量108与有效期5天限制。
- 对高销点：在高峰开始前尽量补到能跨过峰段的有效库存；峰后进入冷却锁，避免同日多次小补。
- 本文仅定义策略与计算口径，用于接入现有“全排列路径模拟+损失最小化”的框架。

## 2. 关键符号与约束
- `C = 108`：点位容量上限。
- `t`：车辆到达该点位的时刻（由路径模拟得到）。
- `I(t)`：到达时的在库。
- `D(a:b)`：区间 `[a, b)` 的累计预测销量（小时级，含起不含止）。
- `D5(t) = D(t : t+120)`：到达时刻起未来5天累计销量。
- `U5(t) = min(C, D5(t))`：受容量与有效期约束的最大可售上限。
- `Q_need(t) = max(0, U5(t) − I(t))`：按“未来5天销量 − 当前库存”得到的可补空间。
- `Lt`：提前期（行驶+作业），小时；仅用于触发与冷却锁边界判定。
- `p`：最小包装粒度（向上取整到 `p` 的倍数）。

## 3. 高峰识别（最多两段）
为保证“高峰期最佳供给”，采用“先验 + 数据驱动”的组合：

### 3.1 先验峰段
- 固定先验：每日 10:00–13:00 视为高峰候选段。

### 3.2 数据驱动峰段（3小时滚动 Top1–2 段）
- 以小时级预测，对“当日”的序列做 3 小时窗口的滚动求和，得到每个连续3小时段的总需求。
- 选择非重叠的 Top1–2 段作为数据驱动峰段；若出现重叠，保留总量更大的段；若总量相同，优先更早的段。
- 与先验段若重叠或相邻（间隔 < 1 小时），可并为一段；若完全不重叠且均显著，则最多保留两段。
- 最终“高峰期”不超过两个时间段；优先保留一个段（Top1）。若业务希望“单峰优先”，仅在 Top2 显著时（如其3小时总量 ≥ Top1 的 80%）才保留第二段。

说明：峰段识别默认按“当前日”进行；为了跨日调度，近峰参考可向前看 36 小时用于排程（如次日早峰）。

## 4. 动态最小补货量阈值（用于跳过判定）
在路径模拟到达时刻 `t`，计算用于“是否访问/是否跳过”的动态阈值 `T_gate(t)`：

1) 峰前覆盖量（首选，当未来存在最近峰段 `[s, e)` 且 `t ≤ e`）
- `T_peak(t) = max(0, D(t : e) + S − I(t))`
- 其中安全库存 `S` 推荐起步用比例法：`S = β · D(覆盖窗口)`，`β` 建议 10%–20%；后续可升级为统计法 `S = z·σ`（σ 为该窗口历史预测误差标准差，z=1.65 对应95%服务水平）。

2) 冷却覆盖量（当近期无峰或已过峰时）
- 设“冷却窗口” `Hc`：高/中/低销点分别为 `24/18/12` 小时。
- `T_cool(t) = max(0, D(t : t+Hc) + S − I(t))`。

3) 阈值合成与包装粒度
- `T_gate(t) = ceil_to_pack( max(T_peak(t), T_cool(t)), p )`。

4) 跳过判定（核心业务规则）
- 若 `Q_need(t) < T_gate(t)`，则在本次路径评估中跳过该点位（不访问）。
- 若 `Q_need(t) ≥ T_gate(t)`，则允许访问，并在不超过 `U5(t)` 的前提下制定本次补货计划量。
- 紧急越权：若跳过将导致“在下一峰段开始前出现缺货且预估损失 ≥ L_urgent”（如 ≥5 盒或 ≥当日销量的5%），则可越权访问（即使 `Q_need < T_gate`）。

备注：当容量/有效期限制导致 `Q_need(t)` 本身很小，且不足以覆盖峰段末，则常规策略会跳过，避免“峰前小补”。仅在触发紧急越权时才执行访问。

## 5. 峰前“有效补满”与补后“冷却锁”
### 5.1 峰前有效补满
- 当 `t` 位于下一峰段开始前（含峰内）时，补后库存应至少覆盖至该峰段结束 `e`：
  - 若 `U5(t)` 或 `C` 限制无法完全覆盖至 `e`，记录“残余风险”，并把下次计划时间设在 `e` 附近的最早可达时点（仍受冷却锁约束）。

### 5.2 冷却锁（避免同日多次小补）
- 补货完成后进入“冷却锁”，锁至 `max(次日 07:00, 下一峰段开始前的 Lt 小时)`；锁内不再召回该点位。
- 紧急越权：仅当预测显示在锁期内会于下一峰段开始前缺货且损失达到 `L_urgent` 时，允许破锁一次。

## 6. 召回触发（何时派车）
以“提前期后的可用库存能否覆盖一个有效窗口”为基准：

`I(t) ≤ D(t+Lt : t+Lt+cover) + S  →  触发召回`

其中 `cover` 优先取“到最近峰段结束 `e` 的时长”，否则取 `Hc`（24/18/12）。

## 7. 与全排列路径评估的衔接
- 在逐点模拟的“到点决策”处，先计算 `Q_need(t)` 与 `T_gate(t)`：
  - `Q_need(t) < T_gate(t)` → 本条路径对该点位“跳过”。
  - `Q_need(t) ≥ T_gate(t)` → 允许访问，并按“峰前有效补满/容量与有效期上限”确定补货计划量；补后进入冷却锁。
- 评分侧：除现有“销量损失优先、时间次之”外，可加两类惩罚以抑制低效访问：
  - 覆盖不足惩罚：本次补货若未覆盖到峰段末 `e`，按潜在损失加权惩罚。
  - 低效小补惩罚：若“避免损失/作业时长”低于阈值 `θ`（单位时间收益过低），对该访问施加惩罚。

## 8. 参数默认与可配
- 峰段识别：先验 10:00–13:00；数据驱动为 3 小时滚动 Top1–2 段，最终不超过两段；当两段均显著时才保留第二段。
- 冷却窗口 `Hc`：高/中/低销 = 24/18/12 小时。
- 安全系数 `β`：默认 15%（可按品类/城市分层配置）；后续可升级为 `S = z·σ`。
- 紧急越权阈值 `L_urgent`：建议起步为 ≥5 盒或 ≥当日销量的 5%。
- 包装粒度 `p`：由业务配置（例如 4 盒/箱）。
- 提前期 `Lt`：根据城市与班次取保守分位（如 P80）。

## 9. 业务边界与说明
- 若 `D5(t) < I(t)`：说明5天内预计消耗不足当前库存，本次访问必跳过。
- 若点位为超高销且容量 108 也难以覆盖到峰段末：允许“补到上限 + 计划下一次到访在峰后最早可达”，并在评分中轻度惩罚“残余风险”。
- 跨日过期/清库规则（如每日 23:00 统一过期）会影响 `D5(t)` 的可售量计算，可在后续扩展为“有效可售需求”。
