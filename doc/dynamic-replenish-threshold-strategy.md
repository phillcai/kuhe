# 基于销量时段分布的动态补货阈值策略

## 1. 策略背景

### 1.1 问题描述
当前补货系统对所有点位使用固定的最小补货量阈值（25件），导致高销量点位被频繁召回：
- **高销量点位**：日销量接近最大库存容量，如点位27（日销量106件，最大库存108件）
- **频繁补货**：按25件阈值可能需要4-5次/天补货，运营效率低
- **资源浪费**：频繁出车增加运营成本

### 1.2 解决目标
- 减少高销量点位的补货频次
- 提高单次补货效率
- 保障高峰期服务质量
- 保持算法简单可维护

## 2. 策略设计

### 2.1 适用范围
- **目标点位**：仅针对高销量点位（日销量周转率 > 0.7）
- **其他点位**：维持现有固定阈值25件
- **降级保障**：异常情况下回退到原有逻辑

### 2.2 高峰期识别算法
```
1. 计算24小时平均销量 = 日总销量 ÷ 24小时
2. 设定高峰识别阈值 = 平均销量 × 2.0倍
3. 识别超过阈值的连续时段作为高峰期
4. 合并相邻的高峰小时形成完整高峰时段
```

### 2.3 时段划分策略
基于销量时段特征，将24小时划分为3个时段：

| 时段类型 | 时间范围 | 调整系数 | 实际阈值 | 策略目标 |
|---------|---------|---------|---------|----------|
| **准备期** | 23:00-10:00 | ×0.7 | 18件 | 夜间低销量时段积极补货，为高峰期储备库存 |
| **主高峰** | 10:00-12:00 | ×1.0 | 25件 | 高峰时段保持正常补货策略 |
| **缓冲期** | 12:00-23:00 | ×1.5 | 38件 | 高峰后延后补货，减少频繁出车 |

## 3. 实施案例：点位27

### 3.1 点位27销量特征
- **最大库存**：108件
- **日销量**：106件
- **周转率**：98%（106÷108）
- **销量分布**：
  ```
  23:00-10:00: 2件  (11小时，低销量)
  10:00-12:00: 47件 (3小时，主高峰)
  12:00-23:00: 57件 (11小时，持续消耗)
  ```

### 3.2 高峰期识别结果
- **平均销量**：106÷24 = 4.4件/小时
- **高峰阈值**：4.4×2.0 = 8.8件/小时
- **识别高峰**：10:00(10件)、11:00(16件)、12:00(21件)
- **主高峰期**：10:00-12:00

### 3.3 策略效果预测
- **改进前**：固定25件阈值，预计4-5次/天补货
- **改进后**：动态阈值，预计2-3次/天补货
- **效率提升**：补货频次减少40-50%，单次补货效率显著提升

## 4. 技术实现要点

### 4.1 核心判断逻辑
```go
// 判断是否为高销量点位
isHighSalesPoint := (dailySales / maxStock) > 0.7

// 时段类型判断
func getTimeSlotType(hour int) string {
    if hour >= 23 || hour < 10 {
        return "preparation"  // 准备期
    } else if hour >= 10 && hour < 12 {
        return "peak"         // 主高峰
    } else {
        return "buffer"       // 缓冲期
    }
}

// 阈值调整
func getAdjustedThreshold(baseThreshold int, timeSlot string) int {
    switch timeSlot {
    case "preparation": return int(baseThreshold * 0.7)  // 18件
    case "peak":        return baseThreshold             // 25件
    case "buffer":      return int(baseThreshold * 1.5) // 38件
    }
}
```

### 4.2 数据来源
- **销量数据**：使用预测数据的24小时分布
- **库存数据**：点位当前库存和最大库存
- **时间数据**：补货车辆预计到达时间

### 4.3 边界处理
- **跨天处理**：23:00-10:00跨天时段的正确识别
- **数据异常**：缺失数据时的降级策略
- **阈值边界**：设置最小值15件、最大值60件的合理范围

## 5. 监控与优化

### 5.1 关键指标
- **补货频次**：每日补货次数变化
- **库存周转**：库存利用效率
- **缺货率**：服务质量保障
- **运营成本**：车辆出行成本

### 5.2 调试信息
在`debugData`中记录：
- 点位销量类型（高/中/低）
- 当前时段类型（准备/高峰/缓冲）
- 动态阈值计算过程
- 高峰期识别结果

### 5.3 优化空间
- **调整系数可配置化**：0.7、1.0、1.5可后台调整
- **时段边界微调**：根据实际效果调整时段划分
- **多点位模式**：扩展到更多高销量点位类型

## 6. 风险控制

### 6.1 降级机制
- 数据获取失败时回退到固定阈值25件
- 高峰识别异常时使用默认时段划分
- 阈值计算错误时使用原始25件阈值

### 6.2 安全边界
- 最小阈值不低于15件
- 最大阈值不超过60件
- 仅对确认的高销量点位启用

### 6.3 监控告警
- 补货频次异常变化告警
- 缺货风险预警
- 策略执行异常告警
